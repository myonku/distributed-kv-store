# distributed-kv-store

一个学习/实验用的分布式 KV 存储，支持**单机**、基于Raft协议的**主从集群**和由Gossip协议+一致性哈希实现的**分片集群**三种模式。

### 构建

```bash
cd cmd/kvnode
go build
```

### 启动

在仓库根目录下已经提供示例配置 `settings.toml`。

```bash
# 在仓库根目录
go run ./cmd/kvnode
```

### 调用示例

```bash
# 写入
curl -X PUT "http://127.0.0.1:8080/kv?key=foo" -d "bar"

# 读取
curl "http://127.0.0.1:8080/kv?key=foo"

# 删除
curl -X DELETE "http://127.0.0.1:8080/kv?key=foo"
```

### 设计说明（简要）

#### 通用

- `模式`：统一的应用配置，支持 `standalone`/`raft`/`chash` 三种模式。
- `存储`：
  - `Storage`：抽象日志 + 状态机存储，支持内存实现和基于SQLite的持久化存储。
- `API与中间层`：
  - `KVService` 接口：对 HTTP 层暴露统一的 KV 操作，下接逻辑层，封装对下层的额外操作。
  - `StartHTTPServer`：对外提供`PUT`、`GET`和`DELETE`三个业务接口。
- `日志`：
  - 默认与 `settings.toml`处于同层目录，可配置。按天生成日志文件。

#### 模式设计

- `单机模式`：
  - 服务入口直接对接存储层，不经过特殊处理。
  - 每条执行依然经过日志。
- `主从集群`：
  - 使用Raft协议实现线性一致性
  - 由Leader节点主导业务服务，其余节点可以转发业务。
  - 逻辑节点间持有内部通信。
  - 状态由Raft集群自动维护。
- `分片集群`：
  - 完全去中心化，但仅支持最终一致性。
  - 逻辑节点间持有内部通信。
  - 基于Gossip协议推进状态，上层负责处理变更并调动数据同步/迁移。
  - 直接基于副本/Replication存储数据，使用“多归属”模型（简化的多主多从）。
  - 支持迁移期间的读/写修复。
